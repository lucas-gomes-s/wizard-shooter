# Combat and encounter design
Status: v0.1; values are proposed.

## Controls and time
Portrait, one floating joystick, automatic attacks, one manual innate button, optional ultimate button from advanced tiers. Touch IDs tracked independently; releasing one finger must not cancel another. Keyboard/gamepad development mapping. Manual abilities target nearest threat or movement direction by definition; aim indicator if needed. No manual aiming requirement. Deadzone, normalized input, configurable left-handed layout, tap targets and safe areas. Auto-pause on focus loss. Resume only after explicit input. Menus consume input and clear held actions on transition.

Fixed simulation tick (initially 60 Hz via Godot physics tick), render independently, seconds and world units rather than frame counts. Explicit session states: loading, playing, paused, upgrade_selection, ending, results. Only playing advances simulation time. Use seeded RNG streams for encounters, upgrades and combat; deterministic ordering for headless tests. Godot physics may not be bitwise deterministic across platforms: target reproducible domain tests, not guaranteed cross-device replay.

## Player runtime
Instantiate from phenotype + trained stats snapshot. HP, cooldowns, charge, status timers and upgrades are runtime only. Basic spell and innate always available; ultimate optional. No equipment. Run XP separate from persistent XP. Death ends run and awards eligible progress; does not retire wizard. Clamp health to max and cast intervals above zero. Avoid invulnerability or self-trigger loops that eliminate challenge.

## Ability definition
Typed resource: id, unlock predicates (phenotype tags, tier, run choices), activation (auto/manual/ultimate/trigger), targeting strategy, range, cooldown_seconds, cost/charge, delivery, effect list, visual/audio cue, trigger limits. Effect definitions: damage, heal, shield, status, spawn, displacement, modify. Delivery: projectile, burst, beam, orbit, aura, summon, trap. Targeting: nearest, strongest, directional, self, random. Conditions: on hit, kill, damage, movement, cast, status. Compose validated effect graphs with bounded recursion/event budgets; no arbitrary executable content. Explicit stacking rules (refresh/stack/replace), damage source and faction, friendly fire policy. All manual abilities signal availability clearly.

POC: Firebolt (auto projectile + burn), Frost shard (auto projectile + slow); Flame dash (manual movement + short trail), Frost pulse (manual area slow/damage). Steam hybrid uses combined effects/alternate targeting, not bonus DPS by default. Stoneborn/Fae may alter ability shape or tradeoffs. Original four upgrades map to run-only move speed, HP, spell damage, casting interval, with sensible caps. Later unlock phenotype-specific upgrades and synergistic choices.

## Simulation order
Read commands -> update AI/intent -> movement -> spawn/projectile advancement -> collision candidates -> damage/status resolution -> deaths and rewards -> XP/level checks -> cleanup -> immutable presentation events. Queue structural modifications to avoid mutating collections during iteration. A level-up pauses after a completed tick; queue multiple choices; if death occurs same tick, death takes precedence. Do not continue spawning after ending. Clamp damage and define contact cooldown per enemy or shared player invulnerability explicitly (POC per-enemy with capped hit feedback). A shot is consumed at first hit unless pierce permits more. Normalize chase direction, handle zero-distance.

## Encounter director
Environment definition: arena, weighted enemy roster, spawn schedule, elite/boss events, difficulty modifiers, reward table, genetic acquisition context. Independent of wizard tier; scale with elapsed time and selected difficulty. Spawn outside visible bounds with safety margin and avoid impossible immediate overlaps. World coordinates and Camera2D separate; despawn according to distance/policy not simply invisibility. Finite POC arena ends after boss defeat; initial duration target 10 min (debug fast mode allowed). Endless increases wave budget over time and offers periodic extraction; define max simultaneous enemies for device performance. Use spawn budget and varied behavior rather than infinite health inflation.

Enemy POC: goblin chaser, spider fast low health, orc slow durable; dragon boss with telegraphed attacks. MVP migrate zombie, knight, vampire, reaper, demon and dragon roles from legacy, with distinct AI. Legacy timing is reference only, not required balance. Telegraph damaging attacks with shape as well as color. Avoid enemy stacking and unfair offscreen hazards.

## Run progression and rewards
Run XP thresholds, choose one of up to three legal upgrades; sample without duplicates, offer safe fallback if exhausted. No upgrade may permanently change genome. Persistent XP and mastery calculated by reward service once at results; finite completion and endless milestones offer different reward tables. See PROGRESSION. Serialize eligible run checkpoints on pause/background and periodic intervals; do not double-pay rewards after recovery.

## Performance and tests
Target 60 FPS on a reference midrange Android device, 30 FPS fallback; identify reference devices during prototype. Measure frame-time p50/p95/p99, memory, thermal behavior and battery over 15-minute runs. Stress 100/300/700 enemies, 1500 as exploratory only; profile before pooling or spatial hashing. Initial scene nodes for player/enemies, lightweight projectiles; avoid allocating textures per tick. Use broad phase grid if pairwise checks dominate; large colliders must occupy all relevant cells. Test movement normalization, touch loss, cooldown floors, deterministic input streams, death ordering, damage, collision edges, XP pause, boss victory, no duplicate results, background recovery. Headless bot policies: stationary, evade, greedy target, scripted ability timing; compare survival and DPS by phenotype and difficulty.
