# First playable prototype

Target Godot 4.5.1 stable (explicit baseline, not a claim that this is the newest engine). Open mobile/project.godot in the editor and press F6/F5 (use F5 for main scene). CLI from repository root:

    godot --editor --path mobile
    godot --headless --path mobile --import
    godot --headless --path mobile --script tests/smoke.gd

Use the actual executable name/path on your OS (on macOS it may be /Applications/Godot.app/Contents/MacOS/Godot).

Controls: WASD/arrows or drag the bottom-left touch area; Space or CAST for the special; pause button; pick an upgrade when prompted. Choose active wizard and partner in Academy. Partner earns 25% XP. Dungeon is deliberately accelerated to a boss at 90 seconds. Endless offers extraction after 30 seconds. Difficulty I–III is independent of character tier. Defeat still yields training XP; victory yields a wizard and essence. Summon costs 10 essence. Two mature tier I characters (40 XP each) can fuse after explicit confirmation; parents retire into the persistent archive. Tier II is the current cap.

Implemented: portrait project, pure seeded genetics prototype (two species, two affinities, mixed body and steam, hidden allele pairs, two possible mutations), phenotype stats, atlas layer composition, fixed-step auto-attacks, manual burst, burn/slow, three enemy types plus simple dragon boss, difficulty, finite/endless, three run upgrades, durable local collection and fusion, shared XP, reward idempotency.

Limitations: no mid-run checkpoint/resume or graphical lineage tree, Android debug export configured but physical device validation pending, original first-pass enemy art, no directional animation, no full trait/catalyst system, no mature-level curve, no graphical discovery journal. Completed training, summons, locks, fusion and archive survive restart. If the app is killed during an unfinished run, that run is discarded without rewards; prior progress is retained. The atlas has one missing Fae/Steam robe variant, mapped to cosmetic robe 0. Hats/robes/staff shapes are neutral cosmetic genes for now; mutation abilities and stats are simplified. Combat uses an unbounded procedural dungeon with sparse pillar collision, following camera and a 120-enemy cap. Balance numbers and 90s encounter are test defaults. Genetic RNG is an explicit small integer algorithm, not yet statistically qualified. The 1000-sample smoke script is not the planned 100k statistical report.

No engine or Android SDK is installed in the authoring environment. Previous build passed GitHub Actions import, smoke (0 failures / 1,000 samples) and headless scene launch. Commit 1e7c141 passed persistence and recovery tests (0 failures), domain tests and headless launch. The art/export revision requires its own CI and physical validation. The original browser game is unchanged.

## Save format v1
Two alternating complete snapshots at user://wizard_profile.0.json and user://wizard_profile.1.json, with schema, revision and SHA-256 of serialized payload. Never overwrite the current verified slot; flush and read back the inactive slot before acknowledging. Load highest valid revision; if neither is valid, block instead of resetting; unsupported versions are preserved. A failed save rolls back in-memory roster, archive, seed counter, essence, receipts and XP together. Reward IDs allocated durably before each run, receipt stored with reward. If reward write fails, retry from result screen. The archive and lock are now accessible in Academy. Files are local, not encrypted; checksum detects corruption, not tampering. No fsync guarantee for power loss, no cloud sync, no recovery of unfinished run. Single writer only; do not launch simultaneous instances sharing a save directory. Tests: godot --headless --path mobile --script tests/persistence.gd.

## Android alpha and combat art
Original pixel matrices in presentation/arena_art.gd define 16x16 goblin, spider, orc and dragon sprites, a cached dark stone floor, fire/ice/steam projectile textures and elemental burst feedback. Runtime creates textures once; no third-party art. Enemy movement bob is two-state, not directional animation. Dragon HP bar uses actual scaled max HP. All graphics remain test art.

The Android Alpha preset targets ARM64, uses Godot 4.5.1 prebuilt debug templates, and includes the JSON sprite manifest explicitly. The CI Android job runs after smoke tests; downloads Java 17 / SDK build tools 35.0.0 and pinned template, exports and verifies a signed debug APK, then uploads a 14-day artifact. Package identifier com.wizardshooter.alpha is temporary. CI uses an ephemeral debug signing key, so later APKs from separate runs may require uninstalling the prior app (which deletes local save data). Use a single locally retained debug key for persistent personal play; stable private signing key and save export/import are future work. Do not use this as a production release. Download the artifact ZIP from the Actions run, extract APK and install on ARM64 Android. No additional permissions are intentionally requested. Android setup reference: https://docs.godotengine.org/en/4.5/tutorials/export/exporting_for_android.html

## Unbounded dungeon world
Both dungeon and endless mode now use world coordinates without a hard arena boundary. Run seed and integer chunk coordinates determine stone tile variants, cracks, decorative runes and sparse solid pillars. 256px chunks are generated only as needed for the visible 360x448 playfield, with bounded texture cache and eviction. Negative coordinates work. The camera follows with smoothing and at most 24px lag; input and HUD remain screen-fixed. Enemies spawn beyond the view (some ahead of movement); ordinary enemies beyond 740px are recycled without XP. A distant boss relocates offscreen beyond 950px without resetting health and has a directional marker. Collision uses simple axis sliding, projectiles hit pillars, and basic enemy tangent steering avoids some obstacles. Procedural rooms, advanced pathfinding, mid-run persistence and device performance profiling are not implemented. Timer/boss and extraction rules unchanged. Existing profile schema unchanged.

## Exploration sites
32% of non-origin chunks have one seeded point of interest (12% treasure, 8% healing, 7% arcane, 5% guarded cache). Walk within 20px to collect ordinary sites; a healing shrine is only consumed with at least 10 missing HP. Treasure grants 6 run XP, 4 training XP and 2 essence. Healing restores up to 35% max HP. Arcane grants +25% damage for 20s (refreshes, not stacks). Guarded caches trigger three guardians within 48px; defeat them and approach the cache to receive 12 run XP, 8 training XP and 4 essence. Guardians do not grant regular kill XP or training; retreating beyond 580px resets the ambush with no reward. Claimed IDs persist throughout the run independent of rendered chunks, and rewards settle with the existing run receipt, including on defeat. No permanent changes to profile schema. Values are first-pass balance hypotheses. Claimed-site memory scales with the number of collected sites, not all visited chunks. No full quest system, interaction prompt, separate map/minimap, or mid-run checkpoint yet.

## Composable combat abilities and talent genetics
Ability catalog compiles data-defined delivery, targeting, damage, cooldown and effects from the phenotype. First operators: nearest-target projectile, self-centered area, and persistent cloud; on-hit burn/chill/slow/cloud, area freeze/shatter, bounded on-death fire bursts. Fire is damage-over-time and death bursts, ice pierces up to three enemies and shatters chilled enemies with the special, steam uses persistent slowing clouds with strongest overlapping DPS. Crystal wings expand special radius and grant a short protective ward; living flame adds burning trail after special. Boss freeze duration is reduced. Four talent alleles: resilient (18% damage reduction), quickcast (12% shorter cast interval), focused (+12% damage), flow (20% shorter special cooldown). Tier I expresses one; Tier II may express two distinct at 70% strength each. Founder and fusion talent RNG independent of original genome draws; inherit one allele per parent with 5% mutation. Old saves derive stable talents from seed on load; old base stats are unchanged. Existing schema v1 accepts optional validated talents. The Academy displays visible spells/passives only. Constants are unbalanced initial hypotheses. No beam, orbit, homing or arbitrary trigger scripting yet. No new affinities or visual talent layers yet; passives are not separately visually expressed. Device validation remains pending.

## Character-specific run upgrades
Mobile uses inherited affinities and expressed genetic traits, not learned schools. Every level-up offers up to three distinct eligible choices: one universal, one affinity-specific, one species/talent/mutation-specific when available; exhausted categories are filled from other eligible options. Independent seeded RNG; offers persist until chosen, no refresh reroll. Rank caps; uncapped modest Vitality fallback avoids an empty offer in endless mode. Run-only changes to compiled kit, base stats, burst parameters and trail rate; never change genome or permanent phenotype. In-flight projectiles retain their effect snapshot. Fire upgrades improve burn, death burst and Inferno; Ice upgrades increase piercing, shatter and control; Steam upgrades improve cloud radius/duration/DPS and vortex. Species and expressed passive/mutation gates matter; no hidden allele or incompatible upgrade shown. Mobile UI shows category, rank and effect. Values are provisional and not yet playtested. No save schema change; no mid-run persistence.

## Phase 1 enemy counterplay
Enemy behavior state machine: spider locks a target and telegraphs a web (4s, 50% movement speed inside); orc winds up before charging in a locked direction, stops on obstacle/recovery; Warlock appears after 42s, maintains range, telegraphs a dodgeable terrain-blocked bolt; Dragon alternates telegraphed breath zone and charge. Freeze interrupts windups/charges; normal global hit immunity, inherited reductions and wards apply to damage. All enemy attack starts require proximity and clear line of sight; basic spell targeting also checks pillars. Enemy bolts/webs capped at 48/16; hazards and telegraphs pause with simulation. New original Warlock sprite, amber attack warnings, web meshes and hostile bolts; provisional damage/range/timing. No advanced pathfinding, full audio, crowd separation, boss phase transitions or balance simulator yet. No save schema change.

## Combat feedback and headless baseline
Damage application now records actual HP removed (excludes overkill), damage taken after mitigation, casts, total run XP, peak enemies and last hit. No balance parameters changed in this revision. Bounded direct-hit particles/floating damage values, defeat particles, enemy hit tint, frozen outline, directional spell trails and player damage border; continuous damage ticks intentionally do not spam damage text. No sound or camera shake yet. Visual quality and frame-time still need physical testing.

Run the actual 60Hz RunModel without rendering or saving: `godot --headless --path mobile --script tools/balance_benchmark.gd -- --seeds=2 --seconds=120 --output=/tmp/balance.json`. CI runs 72 finite encounters (3 affinities x 3 difficulties x 4 simple policies x 2 common seeds). Controlled fixture uses stoneborn, power 100, no expressed talents/mutation; Steam tier II. This isolates affinity partially and is not a complete legal population or human player model. Policies hold movement for 12 ticks, use special in range, prefer affinity upgrades except low-HP vitality; explorer seeks unclaimed sites. Report includes timeout separately from death, HP removed, casts, run/training XP, upgrades, encounters, despawns, peak enemies and CPU time; grouped means and outcome counts. JSON retained as CI artifact. Increase seeds and expand body/talent/upgrade policy comparisons after pilot. Do not tune based solely on two seeds or bot outcomes; retain human feedback and physical FPS testing. No gameplay analytics sent to a server.

## Offline balance optimization
RunModel accepts optional validated bounded tuning parameters; default values preserve previous combat parameters. No live adaptive difficulty. Parameters cover enemy and boss HP/damage, spawn cadence, optional recovery windows, boss add cadence, affinity damage multipliers and XP curve. Benchmark adds boss-aware aggressive/kiting movement, first-upgrade times and boss reach, separate seed ranges, optional all body types. Controlled fixtures omit talents/mutations. Python Optuna search minimizes two-sided challenge bands (competent bot wins D1 35–55%, D2 15–30%, D3 5–15%), early deaths, idle victories, timeouts, affinity spread, lack of boss reach, delayed first upgrades and inverted difficulty ordering. These are project hypotheses, not industry norms. Selection on training seeds only; baseline and selected candidate compared on disjoint validation seeds; report always review-required. No automatic change to default game or genome; use separate approval and larger test cohort. CPU runtime grows with trials/seeds/body types; use `python -m pip install optuna==4.5.0` then `python mobile/tools/optimize_balance.py --godot godot --trials 12 --train-seeds 2 --validation-seeds 5 --output /tmp/optimization.json`. Use --all-bodies and more seeds for validation; --jobs supports concurrent independent headless processes, subject to CPU/memory budget. Manual GitHub Actions workflow for optimization. Pilot is not a statistically definitive result; new bot policy/horizon differs from initial 72-run baseline, so compare within the same experiment.

## Environmental art and movement pass
Original seeded stone floor tiles use three cosmetic district palettes, small chips, cracks, moss, worn inlay borders and subtle runes. Tiles generated once per visible chunk and retain existing eviction bound. Pillars use octagonal bases, chipped caps and shadows; treasure/guarded caches have metal bands and locks, shrines have raised plinths and healing crosses or hovering crystals. Claimed objects stay visibly depleted. Decoration never changes world generation, collision, site placement, interaction radius, balance or save schema. Player walk cycle follows actual travel distance, with restrained idle bob, ground shadow, bounded dust and casting spark. Existing two layered wizard frames remain; no full directional rig yet. All effects use simulation time and motion stops with pause/upgrade overlay. Tests cover distinct frames, tile determinism, district diversity, motion tracking and eviction; visual quality/FPS still require real display/device checks.
